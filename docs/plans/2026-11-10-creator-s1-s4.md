# 创作工坊 S1 与 S4 开发计划

**Goal:** 先用高表现力可信模板、严格参数合同和原生封面完成本机创作闭环，把自由代码的隔离工程留给独立硬关口。

**Architecture:** 在已有 S0 服务上扩展。S1～S3 的模型只输出参数 JSON，原生模板目录生成代码、控件和发布包；S4 只有在下载/联网、执行隔离和外部超时销毁重建全部验证后，才启用原始代码分块合同。

**Tech Stack:** Swift、Foundation/URLSession SSE、WebKit、CryptoKit、现有导入服务与 XCTest；三个纯逻辑协议 Codec 与 Profile 凭据服务已实现，正式参数 JSON Schema 留在 S1.3。

状态：2026-11-10 **S1.0、S1.1 已完成；S1.2 原生连接层与离线合同测试已实现**；验证结果见 [S1.2 实施记录](../features/creator-llm.md)。S1.3、S1.4 与 S4 尚未实施，未进行真实模型联调。S0 的已通过范围及三项失败探针见 [S0 技术记录](../features/creator-s0.md)。本文件不改变已记录的测试结果，不授权付费 API、应用安装、桌面操作或代码提交。

仓库内的编号文档：[02 PRD](02-creator-prd.md)、[03 技术方案](03-creator-technical-plan.md)；本文件沿用原路径，作为 05 阶段计划的权威版本。

本轮已按授权将 S1.1 设置/Profile 补充与规划文档提交为本地回退基线 `37f2c603`（`feat/ai-creator`，未 push），然后实施 S1.2。所有自动化模型请求由 Mock URLProtocol 截获，凭据使用内存存储；完成定向、一次完整门禁和文档检查后暂停，不进入 S1.3。

## 决策与阶段边界

| 编号 | 决策 | 原因与取舍 |
|---|---|---|
| ADR-S1-01 | S1 使用 `TemplateParameterOutput v1`，不输出代码 | 短字段与有界参数适合 JSON Schema；仍要拒绝截断、重复键和未知键 |
| ADR-S1-02 | 每模板 8～12 个有效维度，先于真实模型接入 | 避免只会改色和调速；增加模板开发与性能回归成本，保持固定内核 |
| ADR-S1-03 | 原生快照生成封面后，再冻结最终包 | 卡片需要实际画面；须区分渲染草稿、封闭包及其摘要，保留旧包兼容 |
| ADR-S1-04 | 共享 URLSession SSE + 三协议纯逻辑 Codec | 统一连接、取消和脱敏，三协议分别做合同测试；实际端点可分批联调 |
| ADR-S1-05 | 凭据按 Provider Profile 独立存储并绑定目标 | host 变更使旧关联失效，重试/恢复/跨主机重定向不得转发旧 Key |
| ADR-S4-01 | 下载 delegate 是取消兜底，不是零联网证明 | 回调可能晚于连接；服务器探针和原生事件时序才是验收依据 |
| ADR-S4-02 | 独立执行隔离与宿主外部超时监督是自由代码硬门槛 | 增加宿主复杂度，但不能让任意脚本与当前桌面共享不可控故障范围；不阻塞 S1 |

S1.0 的实际文件及边界见 [参数化模板实现说明](../features/creator-templates.md)；S1.1 的实际实现见 [工程与修订存储](../features/creator-revisions.md)；S1.2 的共享传输、Codec 与凭据服务见 [连接层实施说明](../features/creator-llm.md)；S1.3 及之后的编排/参数/UI 仍待新增。保留已有 `CreatorTemplate`、`CreatorDraftStore`、`CreatorPreview`、`CreatorPublisher` 及 Web 页面宿主，不另造一套不兼容流程。

## 双阶段输出合同

### TemplateParameterOutput v1：S1 实施合同

仅接收一个完整 JSON 对象，必填 `schemaVersion: 1`、`templateID`、`title`、`summary`、`parameters`、`properties`。

| 字段 | 规则 |
|---|---|
| `templateID` | 原生已安装目录枚举，例如拟新增 `stars-v2`；不是代码或 URL |
| `title` / `summary` | 纯文本，分别 1～60 / 1～240 个 Unicode 标量；显示时不解释为 HTML |
| `parameters` | 模板专属的完整键集合；严格数值/布尔/枚举类型，有限值、范围和组合预算 |
| `properties` | 已有控件 ID 子集，每项仅有 `default`；必须与同名参数一致；缺省由原生补齐 |

所有层级禁止额外键，不做字符串转数字；禁止重复键、代码/文件/资源 URL 字段和未知版本。输入总量最多 16 KiB UTF-8。标签、控件类型、范围、排序、显示集合及参数映射由原生目录决定，模型不能提供事件处理器或扩大能力。正式 JSON Schema 与 Swift 校验器从同一目录派生；供应商侧的结构化输出不替代本地校验。

流式响应未结束前只显示进度，不创建可运行半成品；截断不自动补括号。允许有限次数的参数/格式修复；模板内核错误和截图错误不变成模型改源码任务。

### CodeBundleOutput v2：待 S4 解锁

使用 JSON 元数据头列出版本、标题、受限相对路径及能力请求；随后为 `<file path="…">` 原始代码块，不用 JSON 字符串承载源码。应用掌控骨架、SDK、策略、摘要和授权。

在启用前冻结分帧协议：清单与块一一对应、有完整终止标志、按 UTF-8 实际字节计限额；拒绝重复块、缺失块、尾部文本、路径穿越、链接和大小写/规范化碰撞。标签式草案的完整分隔行是保留内容，出现歧义拒绝；比较原生随机边界或长度帧，不能用一个正则切源码。必须覆盖代码字符串内的标签、跨分片分隔符、多字节截断、取消及模型伪造摘要。建议上限 20 个文本文件、单个 256 KiB、总计 1 MiB。

S1 的解析器明确拒绝此版本；“JSON 容易转义错误”的问题不能成为提前打开源码入口的理由。

## S1.0：高表现力可信模板

实际文件：扩展 `App/Services/Creator/CreatorTemplate.swift`、`CreatorPreview.swift`；新增 `App/Services/Creator/CreatorTemplateCatalog.swift`、`CreatorTemplateRenderer.swift`、`Tests/Unit/Creator/CreatorTemplateCatalogTests.swift`、`CreatorTemplateRenderingTests.swift`；同步 `App/Resources/Localizable.xcstrings`。固定内核保留在 Swift 生成器中，本步仍使用三文件包和旧 ID 路由。

1. 固定模板目录、参数类型/单位/范围、控件映射和版本；标签进入现有各语言目录。
2. 为三个模板实现下表维度。优先固定 Canvas2D/粒子内核；固定着色器仍须另测 WebGL、快照与降级，不接受模型 GLSL 或数学表达式。
3. 为每个模板提供至少两组视觉差异明显的预设；确定原生性能档、种子和总资源预算。
4. 以固定种子与测试时钟验证单参影响、最小/默认/最大值及组合最坏输入；同时验证暂停、缩放、恢复和停止。
5. 先完成无需模型的体验基准再进入 S1.2，不能以接上模型代替模板表现力。

| 模板 | 维度 |
|---|---|
| 渐变，10 项 | 主/副色相、角度、对比度、运动速度、波纹尺度、波纹强度、颗粒量、呼吸频率、暗角 |
| 星空，12 项 | 密度、大小分布、拖尾、视差层级、闪烁频率、流星频率、主/副色相、运动速度、时钟开关、九宫格锚点、时钟缩放 |
| 时钟，10 项 | 主/副色相、背景运动、锚点、缩放、12/24 小时制、秒、日期、内置字体枚举、辉光 |

星空初始字段：`starDensity/starSizeSpread/trailLength` 为 0～1；`parallaxLayers` 为整数 1～4；`twinkleHz` 为 0～3 Hz；`meteorRate` 为 0～6 次/分钟；`primaryHue/secondaryHue` 为 0～360；`motionSpeed` 为 0～2；`clockVisible` 为布尔；`clockAnchor` 为固定九宫格；`clockScale` 为 0.5～1.5。

粒子总数、尾迹段数、并发流星、像素面积及 FPS 上限由原生性能档决定，不允许多参数相乘突破总预算。明确区分逐字节可信与“没有漏洞”：固定内核也需要审查和负载验证。

退出条件：每模板 8～12 个有可区分效果的参数、两组预设、边界/组合/生命周期测试通过；效果对比不能仅以 JSON 不同作为证据。可见 UI 的体验评审按仓库授权规则另做。

验证结果：2026-11-10，创作领域 43 通过、0 失败、3 跳过；全量门禁 Python 687 通过，原生 4,767 通过、0 失败、69 跳过。本轮仅完成 S1.0，后续阶段未开始。

实施说明：已提供 10/12/10 个参数与六套预设；保留旧 S0 字节重建，新增整体绘制预算。真实离屏首帧和属性更新使用按需绘制；动画相位、帧率、流星频率在真实 WebKit 中由测试时钟驱动验证。未挂载窗口的原生动画调度、可见桌面流畅度及能耗不能从该测试推断，详见实现说明。

## S1.2：共享模型传输、三协议 Codec 与 Profile 凭据

本阶段同时实现 `openaiCompatible`、`anthropicMessages`、`geminiGenerateContent` 三个纯逻辑 Codec，共享底层 `URLSession` SSE 流式传输与取消/脱敏控制。协议边界以 [03 第 4.4～4.7 节](03-creator-technical-plan.md#44-共享传输层与纯逻辑-codec) 为准，避免三套网络实现。对应 PRD FR-02/10、AC-07/12/17/18 的服务层部分；本节的传输、Codec 与凭据实现已完成，真实端点和产品界面验收未完成。

复用 S1.1 已有的 `App/Services/LLM/ProviderProfile.swift` 和 `CreatorSettingsStore`。已新增文件：`App/Services/LLM/LLMProvider.swift`、`LLMStreamTransport.swift`、`SSEParser.swift`、`LLMProtocolCodec.swift`、`OpenAICompatibleCodec.swift`、`AnthropicMessagesCodec.swift`、`GeminiGenerateContentCodec.swift`、`ProviderCredentialStore.swift` 及 `Tests/Unit/LLM/`。复用 `App/Services/Keychain/KeychainGenericPassword.swift`，使用模型服务专用命名空间，按 Profile 的稳定 ID 独立存储 Key，不按协议或 host 共用。实际实现复用已有 Profile/设置，保持旧规范 JSON 兼容；实现细节由功能文档维护。

1. 复用已持久化的 Profile 三协议枚举、配置代次与配置标识，实现无秘密请求描述；每个请求有独立 Codec 状态，Codec 不访问 URLSession、Keychain、磁盘或 UI。由原生传输校验目标并注入凭据。
2. 实现一套 SSE 分帧与传输生命周期，先用固定响应和注入字节源验证多字节分片、多行事件、心跳、截断、取消、总字节/请求/token 预算和迟到回调；过滤前的思维内容也受原始流限额约束。
3. 分别完成下表的协议合同测试；最终答案只交给 S1.3，思维字段/块不能拼入参数 JSON、日志或工程；未知用量不能记为 0。
4. 实现 Profile 凭据隔离和目标绑定：host 变更必须使旧关联失效、取消旧配置任务并等待显式重新绑定，禁止自动携带旧凭据发送请求。相同 host 的多个 Profile 仍独立；复制 Profile 不复制凭据关联；重试、恢复和跨 host/origin 重定向均不得绕过检查。
5. 共享错误/脱敏覆盖 401、429、网络/协议错误、超时、流内错误及限额；取消必须终止底层请求；不得在 Codec 内偷偷重试、记录原始思维/响应或把 Key 放进 URL。
6. 本轮只验证离线合同；未来依据用户选定的实际 Provider Profile、模型及限额另行开展明确授权的线上联调。线上端点可分批验证，不缩减三协议实现范围，也不随自动化测试发出请求。

| Codec | 必需协议边界 |
|---|---|
| `openaiCompatible` | Bearer；默认 HTTPS/非空 Key；仅显式本地模式且 host 严格为 `127.0.0.1`、`localhost`、`::1` 时允许 HTTP/空 Key；支持 `stream_options.include_usage`、空 choices 用量块与本地无用量返回；过滤 `reasoning_content` 及跨片思维块 |
| `anthropicMessages` | `x-api-key` + `anthropic-version`；顶层 `system`；合并 `message_start` 与 `message_delta` 用量，累计值不重复相加；跳过 `thinking`/签名内容块，仅收正文 |
| `geminiGenerateContent` | 只用 `x-goog-api-key` 请求头，禁止 query 传 Key；`streamGenerateContent?alt=sse`；顶层 `systemInstruction`，`generationConfig.responseMimeType="application/json"`；跳过 `thought=true` 块，解析 `usageMetadata` |

已新增测试组：`SSEParserTests`、`LLMCodecTests`、`ProviderCredentialStoreTests`、`LLMProviderTests`、`LLMStreamTransportTests`；样例和目标主机均使用测试数据，测试不读个人 Keychain。包含 URL/鉴权头和请求 body 的精确断言、正常/异常结束、累计/缺失用量、思维与正文混合、同 host 的两 Profile、host 更改及跨主机重定向。

退出条件：三协议 Codec 均通过合同测试，共享传输可取消且无凭据/思维泄漏；Profile 凭据隔离及 host 变更阻断可验证；不发布半成品，预算有效。不依赖自由代码宿主，也不以某一个实际端点可用代替三协议测试。本轮新增 49 项离线测试，最终定向 87 项通过；完整门禁及跳过项见 [S1.2 验证记录](../features/creator-llm.md)。成功结果仅保留内存中的完整 JSON object，任务仍待 S1.3 严格参数校验；不创建可执行修订、不接 UI。

## S1.3：参数合同与原生编译

拟新增 `App/Services/Creator/CreatorOutputValidator.swift`、`CreatorTemplateCompiler.swift` 及 `CreatorOutputValidatorTests.swift`；扩展已有 `CreatorDraftTests.swift`。

1. 从模板目录产出 `TemplateParameterOutput v1` 的 Schema 和对应 Swift 校验约束，按模板分别约束键集合。

## S1.4：最小创作入口、原生封面与保存闭环

文件：扩展 `CreatorPreview.swift`、`CreatorPublisher.swift` 和现有 Web 预览类；拟新增 `App/Services/Creator/CreatorPosterService.swift`、`Tests/Unit/Creator/CreatorPosterTests.swift`、`App/Views/ControlPanel/Creator/` 的最小界面及 `PanelController+Creator.swift` 类型化操作。完整历史/布局体验留在 S2。

1. 先证明真实离屏 `WKWebView.takeSnapshot` 可捕获所选模板，包括 S1.0 的 Canvas 时钟文字与保留的 S0 时钟 DOM；S0 的 Canvas 像素检测不能替代这个试验。配置捕获区域、`afterScreenUpdates` 和宽度，注意宽度单位为点，编码后复核像素。[Apple 快照接口](https://developer.apple.com/documentation/webkit/wkwebview/takesnapshot%28with%3Acompletionhandler%3A%29)、[配置](https://developer.apple.com/documentation/webkit/wksnapshotconfiguration)。
2. 捕获绑定修订、参数、视口和页面代次；等待加载、布局/字体和首帧就绪。动画不用等待相邻帧完全一样，页面自报 ready 也不是唯一凭据。
3. 原生编码 JPEG；候选限额为总等待 5 秒、最多一次本地重试、长边 1280 像素、文件 512 KiB，保持目标比例；实际 JPEG 必须可解码并包含预期图层。限额变更需更新测试与合同。
4. 将图片原子写入新的待封闭包，填写 `project.json.preview = "preview.jpg"`，核对渲染内容未变，再计算最终摘要和报告。失败/取消/旧代次回调只能保留草稿，不能发布旧图或残缺包；不得为快照偷偷打开窗口或截图桌面。
5. 通过真实导入服务保存，从库卡片使用的预览加载链读回封面；验证改参失效、旧版替换、写入失败和版本恢复。
6. 串联最小界面：描述 → 参数生成 → 检查 → 预览 → 封面 → 保存；在已授权实际供应商联调时完成一次生成和一次修改。此步不自动替换桌面。

退出条件：参数表现力、原生封面、完整包摘要和卡片加载均通过；不能只看 `preview.jpg` 文件存在。对应产品验收 AC-15、AC-16。

## S4：自由代码解锁条件

### S4.1 下载与离线边界

文件：评估扩展 `App/Services/WebWallpaper/WebWallpaperWindow.swift`、`App/Services/Creator/CreatorWebResources.swift`；拟新增 `CreatorDownloadGuard.swift`；保留并扩展 `CreatorPreviewTests.swift` 的探针。

1. 保存带正向对照的 S0 基线。给每个请求独立标识，关联 action、response、didBecome、cancel 与服务器连接/请求时间线；第二条连接已证明关口未通过，但具体底层原因仍需定位。
2. 在导航 action 检查 `shouldPerformDownload`，在 action/response 取消所有不允许的下载转换；生成宿主不返回 `.download`。
3. 两个 `webView(_:navigationAction:didBecome:)` / `webView(_:navigationResponse:didBecome:)` 入口均绑定原生持有的 `WKDownloadDelegate` 并立即 `cancel`；目的地返回 `nil`，重定向取消，不保存恢复数据，不使用内容提供的文件名写盘。[Apple 转换回调](https://developer.apple.com/documentation/webkit/wknavigationdelegate/webview%28_%3Anavigationresponse%3Adidbecome%3A%29)、[目的地回调](https://developer.apple.com/documentation/webkit/wkdownloaddelegate/download%28_%3Adecidedestinationusing%3Asuggestedfilename%3Acompletionhandler%3A%29)、[取消](https://developer.apple.com/documentation/webkit/wkdownload/cancel%28_%3A%29)。
4. 资源 scheme 只提供已冻结资源；评估原生控制的有效 sandbox，禁止 `allow-downloads`。CSP sandbox 在 meta 中会被忽略，自定义 scheme 不能单靠名字提供隔离；S0 的响应头实验已经失败，不得宣称它已封堵。[CSP 规范](https://www.w3.org/TR/CSP3/#directive-sandbox)。
5. 覆盖下载属性、响应附件、MIME 转换、重定向、blob/data、自定义 scheme，以及 EventSource/媒体状态。回调取消可能晚于建立连接，只能作为兜底；“没有落盘”与“没有联网”分开判定。

退出条件：严格模式不产生额外连接或请求，且无落盘/重定向/恢复残留；诊断用 HTTP 响应测试另列，不能用它掩盖请求已经发出。原因未定位或仍有连接即保持自由代码关闭。

### S4.2 独立执行实例与外部监督

拟新增 `App/Services/Creator/CreatorRuntimeSupervisor.swift` 及对应测试；若需要独立受限宿主，先做架构验证并用 `project.yml` 新增目标，不能手改 Xcode 工程。

1. 将配置、数据、资源和生命周期按实例隔离，证明进程/宿主归属与单独终止能力。单独 `WKWebViewConfiguration` 不足以证明进程隔离；本机 SDK 已声明多 `WKProcessPool` 实例不再产生效果。[Apple WKProcessPool](https://developer.apple.com/documentation/webkit/wkprocesspool)。
2. 在被测页面/可终止宿主之外运行原生监督器：用单调时钟发起有界探活及响应检查，不让页面主动自报“正常”续期，也不等待被卡住的 JS 才处理超时。
3. 超时后只销毁自有运行实例；按代次丢弃迟到回调，清理资源，并在重启预算内重建或恢复最后通过版本。隐藏页面、`stopLoading()` 和合作式 `setPaused` 都不是强制停止证明，不杀其他壁纸的 WebKit 进程。
4. 实际执行死循环、微任务饥饿、持续分配、无限日志与异常退出样例；同时保持另一张壁纸运行，记录停止延迟、资源释放和 UI 可用性。CPU/GPU/内存限额单独验收。

退出条件：独立执行隔离、宿主外部心跳超时、受控销毁重建及故障影响范围都有实测证据；超时阈值和重启预算在测试前冻结，不能为过测试无限放宽。

### S4.3 自由代码合同与全入口复验

仅在 S4.1、S4.2 及网络/文件/权限矩阵全部通过后，实施 v2 文件分帧和 `generatedOfflineV1`。验证预览、正式应用、重启、播放列表和恢复保持同一策略；其他尚未适配的入口继续拒绝。三个 S0 探针必须启用并解决，不能跳过后宣称自由代码通过。
