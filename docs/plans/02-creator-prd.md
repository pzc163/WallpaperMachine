## 1. 产品目标

让不熟悉编程的用户，用中文描述想要的动态桌面，通过几轮调整得到可以预览、可修改、可回退，并能在本地持续播放的壁纸。

首版完成以下闭环：

**配置模型 → 输入想法 → 生成项目 → 自动检查 → 独立预览 → 追问修改 → 测试通过 → 保存到壁纸库 → 用户点击应用。**

模型生成和修复时需要网络；已成功保存的首版壁纸，播放所需代码、字体和素材均保存在本地，运行时不调用 LLM，也不依赖在线 CDN。

## 2. 用户与典型场景

目标用户：已经能够使用 WallpaperMachine、愿意配置自己的 API Key，希望通过自然语言制作壁纸的个人用户。

| 场景 | 示例输入 | 预期结果 |
|---|---|---|
| 从零生成 | “深蓝色星空，星星缓慢移动，左下角显示时间，别太耗电” | 自包含的 Canvas/CSS 项目，有颜色、速度等可调参数 |
| 继续修改 | “星星少一点，时间改到右上角，整体偏紫” | 新修订版，上一版保留；旧壁纸继续播放 |
| 使用本地图片 | “以这张照片为背景，加轻微雨滴和视差” | 将选中素材复制进工程；默认只向模型发送素材标识、尺寸等信息 |
| 修复失败 | 生成内容有脚本错误或引用缺失 | 显示具体问题；在预算内有限修复，不无限重试 |
| 调节和应用 | 修改颜色、速度，选择显示器后应用 | 使用通过验证的版本；失败时能恢复先前选择 |

首版不要求用户阅读源代码。源码查看可作为高级入口；直接编辑源码列为后续功能，避免首版同时建设完整代码编辑器。

## 4. 信息架构与界面

顶部导航建议：**壁纸库 / AI 创作 / Steam Workshop / pixiv / 设置**。

创作页分为：

- 工程区：最近工程、缩略图、当前修订、创建/继续。
- 创作区：提示词、素材、对话记录、生成状态、停止按钮。
- 预览区：独立于桌面的效果预览、播放/暂停、尺寸切换和参数。
- 结果区：检查摘要、版本切换、修复、保存到壁纸库、应用到显示器。

本机首版可先复用现有独立预览窗口；不要求第一轮实现完全嵌入的实时编辑器。界面优先显示“正在生成”“正在检查”“需要修复”等用户能理解的状态；详细日志放在可展开区域。

“保存草稿”“保存到壁纸库”“应用到桌面”是三个不同操作。自动生成、自动检查和自动修复均不得自动替换桌面。

## 5. 功能需求与验收

### FR-01 工程管理

S2.2 工程页实现新建、搜索、显示名称重命名、复制和删除草稿。显示名称写入工程内独立 `display-name.json`，不改变摘要绑定的项目身份；复制使用新 UUID 和原生重建、完整运行校验，不复制凭据或自动发布。删除以目录原子改名作为提交点，保留正式库字节和注册表；重启完成残留清理。对话和完整修订历史不默认导出。

工程使用独立 ID，记录标题、创建时间、最新修订、最后通过的修订和关联壁纸 ID。每个修订保存输入摘要、模型标识、模板/SDK 版本、资源包摘要和检查报告。

验收：退出重开后能继续；生成失败仍保留上一版；复制工程获得新 ID；删除草稿时明确说明已保存的壁纸是否受影响，默认保留已保存壁纸。

### FR-02 模型连接

用户通过 Provider Profile 配置服务地址、协议、模型、API Key 和显式本地模式。P0 / S1.2 固定包含 `openaiCompatible`、`anthropicMessages`、`geminiGenerateContent` 三个纯逻辑协议 Codec；共享底层 `URLSession` SSE 流式传输、取消、限额、错误和脱敏控制，不为每个供应商重复建设网络客户端。三协议实现不等于三家线上服务均已联调，实际端点与模型能力需分别验证。

默认强制 HTTPS 和非空 Key，不提供关闭证书验证的选项。仅 `openaiCompatible` 的显式本地模式允许回环、RFC1918 私有 IPv4、IPv6 `fe80::/10` / `fc00::/7` 及合法 `.local` 主机使用 HTTP 与空 Key；公网端点及其他协议不能继承例外，地址与配置变更仍须重新绑定凭据。三协议的鉴权头、system 字段、JSON 模式、用量与思维过滤边界见 [技术方案第 4.5 节](03-creator-technical-plan.md#45-三协议请求与响应边界)。

Keychain 按 Provider Profile 的稳定 ID 独立存储；同协议、同 host 的多个 Profile 不自动共用 Key，复制 Profile 不复制凭据关联。修改目标主机（host 变更）时，禁止自动携带旧凭据发送请求：旧关联失效并取消旧配置任务，用户针对新目标显式重新绑定/填写凭据后才可测试或生成。失败重试、恢复和跨主机重定向不能绕过这一规则；scheme/端口变化也须重新核对目标绑定。详见 [凭据绑定合同](03-creator-technical-plan.md#46-provider-profile-凭据与主机变更)。

“测试连接”显示目标地址和模型并提示可能计费，使用与创作相同的传输、凭据检查及 automatic 三级协商：json_schema → json_object → 提示词 JSON。协商请求与修复共用最多三次请求预算，逐次预留 token；成功后在顶部显示模型、实际生效模式和耗时，支持关闭及状态更新。新配置留空 token 预算使用 24,576 总预留、单次最多 8,192，旧显式预算保持不变。连接失败区分无效凭据、模型不存在、限流、网络/代理、超时和协议不支持。模型列表接口并非必需，允许手填模型名。

验收：三个 Codec 在固定响应测试中均正确生成请求、拼接答案和报告用量；思维内容不混入参数 JSON；缺失用量为“未知”。Key 不出现在工程、日志、提示词、导出数据、URL query 或壁纸页面中，Gemini 必须用 `x-goog-api-key` 头。取消连接测试及时生效；同 host 的两个 Profile 不串凭据，host 变更和跨目标重定向不发送旧 Key。S1.2 已以隔离合同测试覆盖上述传输和凭据行为；真实 Keychain 权限、供应商端点兼容性、连接测试界面与创作闭环仍未验证，不能宣称 AC-17/18 的产品端到端验收完成。当前固定 POST 端点拒绝所有 HTTP 重定向，包括同 origin。

S3 控件补齐：OpenAI-compatible 的模型设置可显式选择 `automatic`（默认）、`schema`、`required`、`disabled`；其他协议显示各自 JSON 合同。模式变更仍走原有配置代次和凭据重新授权流程，不绕过原生输出校验。

### FR-03 生成与修改

S1 输入包括用户描述、已安装模板目录、目标尺寸/比例、性能偏好和当前工程版本。模型仅返回模板名、纯文本标题/摘要、受限参数和已有控件的默认值；不返回代码、文件或资源 URL，不直接操作磁盘或桌面。后续素材能力按 FR-04 的阶段扩展。

修改请求基于一个明确修订生成新修订，不覆盖已验证版本。颜色、位置、速度等可表达为属性时优先暴露为参数，避免每次调参都调用模型。

检查器提供当前模板的原生预设菜单；一键填入完整参数并更新已打开的临时预览，不请求模型。参数有变化时必须“验证修改”后才可保存或应用，不能把预设选择视为已验证的新修订。

S1.3 已实现服务调用：在已有工程内从零生成，或指定 `baseRevisionID` 迭代；模板定义、单位、范围、枚举与预设直接来自原生目录，尺寸/性能另由后续入口接线。用户描述上限 2,048 UTF-8 字节，连同原生上下文受 16 KiB 请求文本上限约束。完整回答可剥离单一 Markdown JSON 围栏，但拒绝解释文本、多段、截断及重复键；所有参数必填，控件默认值须一致。素材与能力白名单目前为空，`assets`、`capabilities`、`files` 等字段即使为空也拒绝。生成的参数同步成为 `project.json` 初始属性值；运行与封面检查仍为 `notChecked`，不授予发布权限。

验收：渐变、星空、时钟每模板 8～12 个作用可区分的参数，至少两组视觉差异明显的内置预设；包含密度、空间结构、动效节奏和布局等维度，不能只有色相与速度。每项参数及组合输入都受原生资源总预算约束。生成期间可以取消；旧请求晚到不能覆盖新请求；无效结构、越界参数、未知键或未完成的流式响应不得运行。

### FR-04 本地素材

这是后续模板资源能力；S1 的参数 v1 合同暂不接收素材字段。启用时需先扩展包资源白名单与摘要合同，不能把任意 URL/代码塞进参数字符串来绕过限制。

用户通过文件选择操作加入图片；应用验证类型、尺寸与大小后复制到工程。首版建议每个工程素材上限 50 MiB，单图上限 20 MiB、长边上限 8192 像素，超限时引导缩小；这些是新模块拟定限制，不是现有导入服务的限制。

验收：素材只能用应用分配的相对资源标识引用；删除原图后工程仍可播放；默认不向供应商上传原图。未来启用参考图理解时，需明确显示哪些图片将被发送。

### FR-05 自动检查

检查分为四层，报告必须记录“通过 / 失败 / 未验证”，不能将未检查项视为通过：

1. 项目结构：文件类型、大小、路径、资源引用、`project.json` 和属性结构。
2. 执行策略：外网访问、越界文件、弹窗、导航、原生桥接和未授权能力。
3. 运行表现：真实 WKWebView 加载、错误/拒绝、资源失败、暂停恢复、缩放重绘、停止可达性。
4. 体验与负载：画面是否存在、尺寸适配、动画回调节奏、资源占用观察；视觉是否符合提示词由用户确认。

静态验证通过后才进入运行检查；运行检查通过不自动代表视觉合格。API 格式检查、JavaScript 语法检查、一次截图或模型自评都不能单独成为“全部通过”。

验收：危险样例被拒绝；缺失资源、未处理异常、页面进程退出等生成明确失败报告；无法取得的指标显示未测得；策略限制失败属于阻断，不提供“仍然应用”绕过按钮。

### FR-06 预览

草稿预览不进入正式壁纸库、不改变桌面，默认静音，不共享桌面网站存储。预览与正式播放使用相同的 AI 内容运行策略、资源内容和 SDK 版本。

至少检查 16:9、16:10 和竖屏比例；首版用模拟尺寸，不必物理接齐显示器。支持暂停/继续、调整颜色等属性、关闭预览和停止运行。

验收：S1 的可信模板在合法参数和组合最坏输入下可暂停、关闭并停止持续渲染；外来死循环源码在运行前拒绝。任意非合作脚本的外部强制停止及独立进程恢复留到 S4 解锁验收，不能把前置拒绝当作强制终止已实现。真实桌面应用另需最终环境检查。

### FR-07 有限自动修复

原生请求的 `maxRepairs` 为 0～2，默认 0；S2.2 提供自动修复开关、1～2 次修复选择和实际尝试计数，最终仍受 Profile 预算约束。S2.1 在静态参数或运行/封面检查失败后，允许预算内重新生成参数；每次从完整静态校验、真实离屏 WebKit 检查和封面捕获重新开始。提示仅含至多 240 标量的脱敏输入摘要、原生失败分类/字段规则、目录约束及已验证参数，未知字段名和原始无效回答不回传；不读取未授权文件，不传 Key、敏感路径或页面日志。运行失败允许换参数/模板，不允许模型修补内核代码。封闭、存储及导入失败不触发模型修复。

验收：首次生成 + 最多两次修复，整轮总共最多三次模型调用，并受 Profile 请求数与累计最大输出 token 预留约束。超时、429、断网、截断、无效输出及兼容 JSON 模式降级均消耗同一预算；子 Job 不得重置预算。401/403、供应商拒绝、配置失效或取消立即终止。429 的 Retry-After 超过 30 秒时停止，不擅自缩短。预算耗尽保留原生失败报告和最后可用版本；崩溃恢复保留已预留次数，绝不重新发请求。

### FR-08 版本与回退

历史修订不可原地修改，记录亲本修订和内容摘要。追问明确指定 `baseRevisionID`，生成草稿的 `parentID` 始终指向该版本。`conversation.json` 保存本地脱敏用户消息、每次尝试/用量/失败与修订引用，不默认导出，不把完整历史或原始模型回答自动发送。选择已验证旧版本会取消当前任务，只改变工程工作/预览目标，不替换正式库内容或桌面。

验收：在第二版生成失败后可继续使用第一版；修改任何代码、素材、属性 schema 或运行策略后，旧测试结论失效。可调参数在已验证范围内无需重新生成；超出验证范围需重测。

### FR-09 保存到库、应用与恢复

“保存到壁纸库”只接收同一内容摘要和同一策略版本的通过报告。发布时再次核对文件；创建稳定的本地壁纸 ID，更新修订时保持该壁纸的合理设置。

S1.4 已实现原生 `preview.jpg`：首帧就绪后获取整个 WebView 的快照，验证编码图片并写入清单 `preview` 字段，再计算最终包摘要。封面失败、超时或过期时保留草稿并阻止发布；修改参数使旧封面与发布报告失效。原有三文件包与新封面包按版本分别校验，不能放宽为“额外文件随意允许”。

S1.4 当轮原生闭环为新建工程/指定旧修订 → Mock 参数生成 → 静态检查 → 无窗口 WebKit 运行与整页快照 → 新的不可变 sealed 修订 → 真实导入服务 → 注册表登记。正式 v2 播放必须持有匹配当前宿主/策略/SDK 的完整报告；普通文件夹导入没有原生许可时仍拒绝 v2。发布日志的 confirmed 是本地保存提交点，之前中断恢复旧字节与登记，之后保留完整新版。其他写入者修改库或登记时保留日志并拒绝覆盖。S2.2 已将恢复接入 PanelController 首次 start，并由原生卡片加载封面；生成入口停在完整校验后的待保存态，保存通过显式按钮执行。AI 数据的旧备份/恢复/搬迁被明确阻止，尚不支持自动迁移。

“应用”允许选择当前显示器或已有的全屏应用能力。应用前保留原显示器选择和最后可用版本；失败时恢复。首次运行正常后才把候选版本记录为新的已成功应用版本。

验收：写入途中退出、空间不足、库盘断开、导入失败和桌面首次加载失败均不留下可播放的半成品；恢复动作自身失败时保留恢复信息并清晰提示。启动、播放列表和恢复等入口同样执行 AI 运行策略，不只限制创作页的按钮。

### FR-10 成本、隐私与错误体验

显示本次请求次数、耗时、模型返回的 token 用量；三个协议归一化请求级统计，累计更新不能逐片相加。过滤思维内容不扣除其实际用量；供应商不返回时标记“未知”，包括无用量的本地兼容端点。只有配置可靠单价时才显示估算费用。客户端请求上限不等于供应商账单硬上限；需要费用硬限额时引导在供应商侧设置。

默认不上传完整壁纸库、Steam 登录信息和系统诊断；对话和草稿留在本机。错误界面提供重试、改模型、查看报告和返回上一版，不能只显示“生成失败”。

验收：401 不盲重试；429 遵守可用的重试提示且计入预算；取消后停止后续调用，但明确已发送请求仍可能被供应商计费；日志做脱敏和限量。S1.2 在每次发送前持久化请求次数和最大输出 token 预留，失败与 JSON 模式降级也消耗预算；成功结果只报告最终请求的可用用量，失败尝试的用量未知，不能据此声称整个任务的账单已知。累计输出预留不包含输入或供应商额外计量，不是费用硬上限。S1.3 将请求次数、输出预留、最后成功请求的可选用量、模型/Profile 配置标识和提示词摘要绑定进不可变修订；不保存原始流、思维块或完整系统提示词。S1.3 单独调用仍不自动修复参数；S2.1 编排用对话轮次作为整轮预算账本，子 Job/修订只记录自身次数并引用轮次 ID。完整回答即使随后未通过静态校验，也保留已返回用量；断流或无用量保持未知。预算先持久化再发请求，崩溃可能保守多计一次，不返还额度。

按需真实联调入口默认跳过，必须显式启用环境变量并仅选择 `CreatorLiveSmokeTests`，完整日常门禁拒绝启用它。每次最多一个模型请求、2,048 输出 token 预留；Key 由测试运行器一次性本机内存通道交付，使用内存凭据存储，不进入 Xcode 子进程环境或个人 Keychain。保存的测试证据是已校验参数、用量、原生报告与固定失败码，不记录原始 SSE、思维内容、Key 或错误响应体。调用说明见 [联调入口](../features/creator-publication.md#opt-in-live-smoke)。本轮没有执行真实请求，此入口存在不代表供应商已经通过验收。

## 6. 状态与操作规则

工程修订状态：

`草稿 → 生成中 → 待检查 → 检查中 → 可预览/可发布`。

失败可进入“待修复”；修复生成新修订，再走检查；取消进入“已取消”，保留此前有效修订。发布和显示器上的应用状态单独记录，不能与“某个生成任务完成”混为一个状态。

| 状态 | 可以做什么 | 禁止什么 |
|---|---|---|
| 生成中 | 查看进度、取消，使用已有版本 | 执行流式半成品 |
| 待修复 | 查看问题、有限修复、修改提示词、回退 | 把阻断错误标成已通过 |
| 可发布 | 用户看效果、调参、保存到库 | 自动替换桌面 |
| 应用中 | 显示进度、保留原版本 | 提前删除回退所需内容 |
| 应用失败 | 回到旧版本、查看原因 | 将失败版本记为成功 |

## 7. 质量目标与度量

以下为计划目标；S0/S1 取得基线后冻结，不是当前性能承诺。

| 项目 | 首版目标及测量方法 |
|---|---|
| 参考环境 | Apple Silicon，macOS 15+；首先记录实际测试 Mac 的型号、内存、系统、显示分辨率 |
| 生成基准 | 固定语料 v1 的 10 条中文提示词 × 3 轮；区分 Mock 与 live，记录实际模板、失败及未知用量；完整 live 样本才可判断目标，入口见 S2.3 验收文档 |
| 可运行率 | 基准集合最终检查通过率目标 ≥80%；样本少，不外推为任意提示词保证 |
| 视觉可用率 | 与可运行率分开；由用户按布局、效果、可读性、偏好确认，记录不满意原因 |
| 预览启动 | 已生成本地小型模板的首个可见内容目标 ≤5 秒；不包含模型生成和大素材下载 |
| 异常停止 | 页面失去响应后目标 5 秒内报告并允许停止；无限循环场景须验证，不能依赖页面自报心跳 |
| 动画 | 默认 30 FPS 目标；参考模板以 1920×1080 测试，回调节奏与实际桌面流畅度分别记录 |
| CPU/GPU/内存 | 对比同效果固定模板和空闲基线；S0 定义可测口径和阈值。无法精确归属某 WebContent 进程时不显示伪精确数值 |
| 长时间运行 | 基准模板至少运行 30 分钟，观察持续内存增长、暂停恢复和异常；实际电池耗电另做授权实测 |
| 离线能力 | 断开网络后新启动已保存壁纸，画面及本地时钟/交互正常，且没有外部请求尝试 |
| 既有功能回归 | 原有导入、Scene/Video/Web 播放入口、预览、属性和显示器选择相关自动测试保持通过 |

2026-11-11 实测：qwen3.8-flash-next / schema、固定语料 v1 的 30 个样本全部首次通过（首次/最终均 100%，达到本配置 ≥80% 目标），模板选择 30/30 正确；三个模板持续离屏运行 1800.093 秒，540 次采样均正常。该结果不外推到任意模型/提示词，也不替代视觉可用率、真实桌面及能耗验收。

不以“生成用时小于固定秒数”作为所有外部模型的硬验收。界面应持续反馈进度，并给出配置化超时和可取消能力。

## 9. 交付阶段

1. **技术验证**：三个固定模板，证明草稿预览、策略限制、错误捕获、可靠导入和失败恢复。
2. **生成闭环**：先扩展高表现力可信模板，实现共享传输与三个协议 Codec，并分别通过离线合同测试；再按用户选定的实际 Provider Profile 做授权联调，让其输出参数，完成一次修改、原生封面和本地保存。线上端点可以分批验证，不能据此缩减三协议编码范围。
3. **可用首版**：版本回退、最多两次修复、取消、成本记录和完整验收。
4. **扩展与发布准备**：按本机试用反馈决定文生图/WebGL/音频等顺序，另行规划对外发布。

## 10. 后续需要确定的事项

不影响文档评审，但在对应阶段实施前要确定：

- 实际联调的供应商端点、模型、所用 Provider Profile 和本地模型需求；三协议范围已经确定，服务端能力差异在 Profile 中显式记录。
- 每次生成允许的请求次数和单次 token 上限；首版建议总请求数上限为 3。
- 首批效果偏好；S1 已确定星空/粒子、时钟、渐变，模板资源/图片动效后续扩展。
- 模板参数路线已确定；自由代码是否启用只由 S4 的隔离与外部停止证据决定。
- 对外发布的产品名、发行方式及商业化方向，留到本机首版可用后决定。

本文没有假定用户已批准具体 API 费用、安装新应用、替换桌面或发布软件。实现过程中到达这些步骤时，应依据届时明确的操作指令执行。
