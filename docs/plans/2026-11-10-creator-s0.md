# Creator S0 implementation plan

**Goal:** Exercise local draft preview, restricted WebKit execution, real library import and recoverable publication with fixed examples, without an LLM or desktop changes.

**Architecture:** Drafts are immutable validated bundles. A separate creator loader retains the installed-preview path checks. Publication uses WallpaperImportService with a durable journal and rollback. S0 starts with trusted templates and bounded parameters; arbitrary generated code remains experimental until isolation and stop behavior have evidence.

**Tech stack:** Swift, Foundation, CryptoKit, WebKit, existing import service, XCTest.

## Tasks

1. Add a draft store and three deterministic templates (gradient, stars, clock). Validate relative paths, links, limits and content hashes. Tests reject traversal and mutation after validation.
2. Add an offscreen creator preview using restricted resources, no capture, no external navigation/network, and a disposable data store. Exercise properties, pause, resize, cancellation, stop and error callbacks in real WKWebView.
3. Add a publisher using the actual import service. Keep immutable recovery copies and a durable journal. Test first import, replacement, injected failure and recovery after a recreated service.
4. Check that a published trusted template retains its offline policy and detects changed bytes. Do not expose arbitrary generated code to the unrestricted installed host.
5. Run targeted tests then the repository gate once. Record absent tools, blocked checks and unverified desktop behavior truthfully. No Release delivery is claimed by S0.

## Scope and gates

Fixtures and library data live in unique temporary folders, never the user's library. No visible windows, audio devices, Steam access, model APIs or automatic wallpaper replacement. Existing compatibility Web pages retain their behavior. A passing offscreen test is not evidence of visible desktop performance. A rejected isolation probe blocks unrestricted code generation, not publication of a byte-verified trusted template.

## Outcome

The trusted-template workflow passed its targeted checks and the routine gate on
2026-11-10. Arbitrary-source isolation did not pass: download, EventSource and
media probes remain explicitly reproducible, known-failing opt-in checks. The
next model integration may generate bounded template parameters only. See
[the implementation and verification record](../features/creator-s0.md) for the
precise scope, counts and limits; no desktop-level recovery or creator UI is
claimed by this prototype.

The [S1 and S4 follow-up plan](2026-11-10-creator-s1-s4.md) specifies richer
template parameters, a native cover and the separate download/process-isolation
gates. It is planned work, not additional S0 verification evidence.
